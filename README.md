# Яндекс Алиса + Ollama Cloud + Serper

Форк шаблона [alice-gemini-serper-template](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template).
Вместо Gemini используется облачная Ollama с моделью **kimi-k2.7-code**. Локально устанавливать Ollama не требуется.

## Как работает диалог

Запустите приватный навык и задайте вопрос. Алиса отвечает на него в той же реплике: ждать подтверждения и говорить «ответ» не требуется. Ответ готовится синхронно, без фоновых заданий.

На весь обработчик выделено **3600 мс**, чтобы оставить запас до [лимита Яндекса 4,5 секунды](https://yandex.ru/dev/dialogs/alice/doc/ru/response), включающего сеть и установление соединения. Внутренние ограничения:

| Операция | Максимальное время |
|---|---|
| Redis: проверка лимита и загрузка истории одним атомарным запросом | 250 мс |
| Serper, если нужен поиск | 600 мс |
| Ollama Cloud | 2800 мс, дополнительно сокращается до остатка общего бюджета минус 300 мс |
| Redis: сохранение ответа | 250 мс, внутри общего бюджета |

При общем дедлайне все незавершённые HTTP-вызовы отменяются, навык сразу возвращает короткое сообщение о таймауте. Отдельной команды получения результата нет. Дедлайн приложения не гарантирует общий сетевой лимит при холодном старте или сетевых задержках.

Модель остаётся **kimi-k2.7-code**. Она может не успеть сформировать полный ответ за этот срок, особенно с reasoning или после поиска; тогда колонка озвучит сообщение о неудачной попытке. Реальные задержки нужно измерить после развёртывания. Пятисекундный бюджет Serper отменён ради ответа в одной реплике.

## Ограничение частоты

**Один новый вопрос на весь навык в 15 секунд**, общий для всех сессий, пользователей и экземпляров Vercel. Lua-скрипт атомарно загружает историю, проверяет повторную доставку и выдаёт разрешение. Неудачная генерация тоже расходует интервал; отказ по лимиту не продлевает его. Повторная доставка последнего завершённого вопроса возвращает сохранённый результат. Повтор запроса, который ещё выполняется, возвращает короткое сообщение без новой генерации.

При отказе Redis новые генерации блокируются: запасного счётчика в памяти нет. Если предыдущий запрос аварийно оборвался, следующий вопрос можно задать после общего 15-секундного интервала. Этот лимит ограничивает дорогостоящие генерации, но **не общее количество HTTP-запросов и Redis-операций** — для них нужен WAF.

## Настройка

Нужны Node.js 22+, проект Vercel, аккаунт Ollama Cloud и база Upstash Redis с REST-доступом.

1. Импортируйте свой форк в Vercel. Сборка не требуется; зависимости устанавливаются из `package-lock.json`.
2. Создайте Redis в [Upstash](https://console.upstash.com/) и скопируйте REST URL и токен с правом записи. Используйте отдельную базу рядом с регионом функции. Preview-развёртываниям нужна отдельная база и отдельные секреты.
3. В Vercel → Settings → Environment Variables задайте:

| Переменная | Значение |
|---|---|
| `OLLAMA_API_KEY` | Ключ из [Ollama](https://ollama.com/settings/keys) |
| `OLLAMA_MODEL` | `kimi-k2.7-code` (значение по умолчанию) |
| `SERPER_API_KEY` | Ключ [Serper](https://serper.dev/), необязательно |
| `WEBHOOK_SECRET` | Случайная строка минимум 32 символа |
| `ALICE_SKILL_ID` | Идентификатор вашего навыка Яндекса |
| `UPSTASH_REDIS_REST_URL` | `https://YOUR-DATABASE.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | REST-токен Redis с правом записи |

Сгенерировать секрет локально, не сохраняя его в Git:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

4. Выполните Redeploy. `vercel.json` задаёт платформенный максимум 10 секунд; собственный дедлайн обработчика составляет 3,6 секунды.
5. В Яндекс Диалогах задайте HTTPS Webhook URL:

```text
https://YOUR-PROJECT.vercel.app/api?token=YOUR_WEBHOOK_SECRET
```

6. Сделайте навык приватным и проверьте полный цикл в тестере и на колонке. Секрет URL даёт доступ к backend: не публикуйте этот адрес, скрывайте query string в журналах и скриншотах.

Старые `GEMINI_API_KEY` и `GEMINI_MODEL` больше не используются; удалите их из настроек проекта. Реальные ключи не добавляйте в исходники, GitHub или сообщения. GET `/api` — только проверка запуска обработчика, она не проверяет конфигурацию, ключи, Redis или модель.

## Данные и безопасность

- Webhook требует секрет и ожидаемый `skill_id`; идентификатор навыка сам по себе не является аутентификацией Яндекса.
- Модель получает вопрос и до восьми последних сообщений. Serper получает текущий вопрос только при срабатывании проверки поискового намерения.
- Redis хранит последний статус, ответ и ограниченную историю с TTL **180 секунд** после записи. Новая запись обновляет TTL; после бездействия история исчезает. Ключи сессий — HMAC, без открытых идентификаторов. Хранилище не получает ключи Ollama или Serper.
- История не принимается из клиентского `session_state`. Секреты, тексты вопросов, ответы и сырые ошибки провайдеров код не пишет в логи.
- Внешние адреса фиксированы, перенаправления запрещены, объём входа/выхода и время запросов ограничены.
- Поиск использует до трёх кратких описаний, полные страницы не загружаются. При недоступном поиске модель получает явный статус `unavailable`.
- Ответы модели нельзя считать проверенными фактами. Отделение поисковых данных и системного промпта снижает риск prompt injection, но не устраняет его.

Полное ревью и рекомендации: [SECURITY_REVIEW.md](SECURITY_REVIEW.md).

## Проверки

```sh
npm ci
npm test
npm audit --omit=dev
```

Тесты используют подменённые HTTP-провайдеры и хранилище, не расходуют API-квоты. Проверяются прямой ответ, глобальный лимит, дубликаты, история, отмена поиска через 600 мс и общий дедлайн 3600 мс, в том числе при зависшем Redis. Реальный Redis и голосовой диалог требуют проверки после развёртывания.

Сторонних runtime-зависимостей нет: SDK Vercel и `waitUntil` удалены. Код использует встроенные возможности Node.js.

## Ограничения стабильности

- Сервер возвращает ответ в рамках бюджета приложения либо сообщение о неудаче. Время сети, холодного старта и планирования платформы остаётся вне его контроля.
- Kimi может не успеть ответить. `message.thinking` не озвучивается; пустой или обрезанный по лимиту ответ считается ошибкой. Лимит генерации — 2048 токенов. Не все модели поддерживают отключение reasoning, поэтому неподтверждённый параметр `think: false` не передаётся.
- Поиск включается по ключевым словам и может пропустить запрос, требующий актуальности. После таймаута поиска модель получает статус `unavailable`.
- Сохранение результата выполняется до возврата ответа. Если Redis откажет на этой стадии, ответ всё равно озвучивается, но история/кэш могут не обновиться. Автоматических повторов платных запросов нет.
