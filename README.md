# Яндекс Алиса + Ollama Cloud + Serper

Форк [alice-gemini-serper-template](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template).
Модель по умолчанию — **gemma4:31b** в Ollama Cloud. Redis и установка Ollama не требуются.

## Настройка

1. Импортируйте свой форк в Vercel. Среда — Node.js 22+, отдельная сборка не требуется.
2. В Settings → Environment Variables → Production добавьте:

| Переменная | Обязательна | Значение |
|---|---|---|
| `OLLAMA_API_KEY` | Да | Ключ из [Ollama](https://ollama.com/settings/keys) |
| `WEBHOOK_SECRET` | Да | Собственный случайный пароль минимум 32 символа |
| `SERPER_API_KEY` | Нет | Ключ [Serper](https://serper.dev/); без него поиск выключен |
| `OLLAMA_MODEL` | Нет | По умолчанию `gemma4:31b` |
| `ALICE_SKILL_ID` | Нет | ID навыка, если нужна дополнительная проверка адресата |

WEBHOOK_SECRET не выдаёт никакой сервис: его создаёте вы. Сгенерируйте в терминале:

```sh
openssl rand -hex 32
```

3. Выполните Redeploy последнего main после изменения переменных.
4. В Яндекс Диалогах укажите Webhook URL:

```text
https://YOUR-PROJECT.vercel.app/api?token=YOUR_WEBHOOK_SECRET
```

Вместо YOUR_WEBHOOK_SECRET вставьте ту же строку, что указали в Vercel. URL с token нельзя публиковать. Сделайте навык приватным и проверьте в тестере, затем на колонке.

`ALICE_SKILL_ID` лишь отсеивает запросы, адресованные другому навыку. Это не доказательство происхождения запроса: ID можно подделать. Если переменная отсутствует, дополнительная проверка адресата отключена, но секрет URL по-прежнему обязателен.

Старые `GEMINI_*` и `UPSTASH_REDIS_REST_*` больше не используются; их можно удалить из настроек.

## Диалог и таймауты

Задайте вопрос — Алиса отвечает в той же реплике. Команды получения результата и фоновых заданий нет.

Общий бюджет обработчика — **3600 мс** от входа в handler, Serper — **1800 мс**, Ollama — до **2800 мс**, дополнительно ограничено остатком общего бюджета. На сетевой обмен с Яндексом остаётся номинально 900 мс до его лимита 4,5 секунды. При дедлайне HTTP-вызовы отменяются и возвращается короткий ответ о таймауте. Холодный старт и задержки сети могут нарушить общий срок доставки.

Для Gemma 4 явно задано `think: false`, лимит генерации — 150 токенов. Это сокращает время на рассуждения и длинные ответы. Модель всё равно может не успеть при высокой нагрузке. Если в Vercel уже задана OLLAMA_MODEL, измените её на `gemma4:31b` или удалите для использования нового значения по умолчанию и выполните Redeploy. При систематических таймаутах потребуется более быстрая модель. Пятисекундный бюджет Serper отменён ради прямого ответа колонки.

## Диалог без пауз

Ограничение частоты вызовов удалено: следующий вопрос можно задавать сразу. Кэш повторной доставки последнего сообщения сохранён, чтобы один и тот же webhook не запускал модель повторно внутри процесса.

История и ответы хранятся только в памяти: до 8 сообщений по 1200 символов, запись живёт до 180 секунд после обновления. Другой экземпляр Vercel или перезапуск теряет контекст. Число записей ограничено 1000; истёкшие записи очищаются при обращении. Это ограничение объёма памяти, а не задержка между репликами.

Промпт рассчитан на свободный разговор на любые темы, а не только программирование. Он различает поиск, который не запускался, не дал результатов или завершился ошибкой. Правила самого провайдера сохраняются. Для актуальных фактов модель не должна выдумывать данные.

## Поиск

Запрос в консоли Serper не доказывает, что webhook успел получить результат. Раньше обработчик отменял поиск через 600 мс; теперь ждёт до 1800 мс в пределах общего бюджета 3600 мс. На модель остаётся остаток времени, но не более 2800 мс. Если поиск вернул краткий ответ или описание страницы, а модель не успела, навык озвучит этот фрагмент с явным вводным текстом «В поисковой выдаче…».

В Function Logs запись `Web search completed` содержит `status`, `reason`, `httpStatus` и `durationMs`, без вопросов/результатов/ключей. Причины: `timeout` — отмена ожидания, `http_error` — отказ API (код рядом), `missing_key` — отсутствует SERPER_API_KEY, `time_budget` — исчерпан бюджет запроса, `request_error` — прочая ошибка сети/формата ответа. `available` означает полученную выдачу, `empty` — отсутствие результатов. В обычном разговоре поиск не запускается и такая запись не создаётся.

## Диагностика

- **503**: неверна конфигурация. В Function Logs найдите `Webhook configuration invalid` и `fields`: перечислены только имена проблемных переменных, без значений ключей. Для запуска достаточно OLLAMA_API_KEY и WEBHOOK_SECRET минимум 32 символа без пробелов по краям. Затем Redeploy.
- **403**: в URL отсутствует или неверен `?token=...`.
- **400**: неверный формат запроса либо ALICE_SKILL_ID задан и не совпадает с адресатом запроса.
- GET `/api` проверяет только запуск обработчика, а не ключи или готовность провайдеров.

## Безопасность и проверки

Адреса Ollama/Serper фиксированы, редиректы запрещены; входные/выходные данные ограничены по объёму и времени. Клиентская история не принимается. Секреты и содержимое диалога приложение не пишет в логи. Модель не получает ключи и инструменты выполнения кода; reasoning не озвучивается.

Вопросы/история передаются Ollama Cloud, текущий поисковый вопрос — Serper. Поиск использует краткие описания до трёх результатов, полные страницы не открывает. Разделение данных и системного промпта не гарантирует защиту от prompt injection или ложных фактов.

```sh
npm ci
npm test
npm audit --omit=dev
```

Сторонних runtime-зависимостей нет. 20 тестов проверяют валидацию, прямой ответ, дедлайны, отсутствие пауз между вопросами, срок и объём памяти, дубликаты, историю, промпт, диагностику поиска и выдачу найденного фрагмента при таймауте модели. Реальные ключи, скорость Ollama и голосовой диалог требуют проверки после развёртывания.
