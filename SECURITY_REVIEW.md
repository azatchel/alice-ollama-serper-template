# Безопасность и стабильность

26 октября 2026 года. Актуальная версия использует Ollama Cloud и необязательный Serper; Redis удалён. Ревью исходников и автоматические тесты выполнены, развёрнутый сервис с реальными ключами не проверялся.

## Реализовано

- Обязательный WEBHOOK_SECRET минимум 32 символа, сравнение timingSafeEqual. ALICE_SKILL_ID необязателен и проверяет только адресата, а не подлинность отправителя.
- Проверка протокола/сессии/сообщения, вход до 32 КиБ, реплика до 1200 символов. История из клиентского session_state не принимается.
- Общий бюджет приложения 3600 мс; Serper 600 мс; Ollama до 2800 мс с учётом остатка. Общий дедлайн отменяет внешние запросы, фоновая генерация отсутствует.
- Фиксированные адреса провайдеров, запрет редиректов, ограничение размера ответа, таймаут до конца чтения тела.
- Только message.content; reasoning и сырые ошибки не озвучиваются. Модель не получает API-ключи, код не выполняет команды модели. Логи приложения не содержат текстов диалога/секретов; диагностика конфигурации выводит только статические имена переменных.
- Локальное хранилище ограничено 1000 записями, TTL 180 секунд после записи. История до 8 сообщений по 1200 символов, HMAC-ключи без открытых идентификаторов. При заполнении — отказ, без вытеснения активных записей.
- В одном процессе проверка и резервирование слота синхронны, без await. Дубликаты возвращают кэш в том же процессе, старое завершение не перезаписывает новый запрос.
- Сторонних runtime-зависимостей нет, npm audit не находит известных уязвимостей на дату проверки.

## Основные остаточные риски

**Лимит приблизительный.** Один новый вопрос в 15 секунд действует только в рамках процесса. Vercel может поднять несколько экземпляров; перезапуск сбрасывает лимит, историю и дедупликацию. Общий строгий лимит и ограничение расходов этим кодом не гарантируются. Возврат к общему хранилищу возможен позже при необходимости; сейчас Redis исключён по запросу пользователя.

Рекомендации: приватный навык, WAF/rate limits на входе, доступные лимиты расходов у Ollama/Serper, дневной бюджет/kill switch. Даже стабильный одиночный процесс допускает до 5760 вопросов в сутки. HTTP-вызовы не ограничены локальным лимитом генераций. После отмены HTTP-запроса провайдер может продолжить вычисление/списание.

**Секрет URL может утечь.** token может оказаться в инфраструктурных логах, истории браузера или скриншотах. Знание секрета позволяет обращаться к навыку; skill_id можно подделать. Ограничьте доступ к настройкам и логам, маскируйте token и меняйте секрет при утечке. Ротация секрета меняет HMAC-ключи и сбрасывает доступ к прежнему состоянию/лимиту. Не полагайтесь на IP из тела или произвольного X-Forwarded-For.

**Скорость Gemma не подтверждена.** Gemma 4 31B используется с `think: false` и лимитом 150 токенов, но может не успеть ответить после поиска или при нагрузке. Дедлайн приложения не включает холодный старт до входа в handler и сетевую доставку. Проверяйте p50/p95, долю таймаутов и качество поиска на колонке. При частых неудачах понадобится более быстрая модель; увеличение таймаута не решает лимит Яндекса 4,5 секунды.

**Контекст недолговечен.** При другом экземпляре/перезапуске история теряется, после 180 секунд без обновления запись истекает. Если нужна стабильная память между репликами, потребуется отдельно реализованное внешнее состояние. Автоповторов платных вызовов нет. Авария расходует текущий локальный cooldown, но новый вопрос после 15 секунд допустим. GET /api — только liveness.

**Внешние данные недоверенные.** Ollama Cloud получает вопрос/историю, Serper — поисковый вопрос. Не передавайте чувствительные сведения; учитывайте правила хранения у провайдеров. Поиск с коротким таймаутом может не сработать; используется регулярное выражение и краткие описания трёх результатов. Промпт/JSON-разделение не гарантируют защиту от prompt injection и ложных фактов. Для серьёзных решений сверяйте первоисточники.

## Проверки

17 тестов проходят: авторизация/валидация, прямой ответ, протокол Ollama, локальный интервал между сессиями, дубликаты и история, заполнение/истечение памяти, независимость разных экземпляров, ошибки провайдеров/хранилища, скрытие reasoning, ограничение тел и отмена HTTP, таймаут Serper 600 мс, общий дедлайн 3600 мс при зависших вызовах, HMAC-изоляция, безопасная диагностика, запуск без Redis и ALICE_SKILL_ID.

Таймеры бюджета проверяются виртуальным временем, HTTP-провайдеры подменены. Живой сервис, реальные задержки, расходы и голосовой сценарий не проверялись.

Перед использованием: проверить вопрос/ответ на колонке, повтор раньше/позже 15 секунд, отсутствие/неверный token, несовпадение необязательного skill_id, отказ поиска/модели и отсутствие ключей/текстов в инфраструктурных логах. Сделать Redeploy после изменения переменных.
